Bit-packing for DNA methylation. Arrays and whole genomes in one binary format family, where analysis is bitwise — and so stays fast across a thousandfold of scale, from 28K probes to 29M CpGs.

Fetch — nothing ships with the binary

No reference data is bundled: no coordinates, no feature sets, no example methylomes. One fetch fills a digest-verified store shared by every tool in the suite — $YAME_DATA_HOME, default ~/.local/share/yame. Everything else on this page runs against those files, and every output shown was captured from the command above it.

A name is what the browser shows — hg38, hg38/KYCG, hg38/data — and it is a scope: hg38 takes everything under it. Narrow within it with -g, whose terms are ANDed and match a file's name, source, collection, title or upstream database.

yame fetch            # browse: species, platform, files
yame fetch hg38/KYCG  # the hg38 knowledgebase + coordinates
yame fetch hg38/data  # 53 MB of real methylomes to try
yame fetch hg38/KYCG -g chromatin  # 3 sets, not 32
yame fetch hg38 -g celltype       # across the whole genome

Every fetch says what it will do and asks first. -n prints that plan and stops, successfully, so a script can check before committing:

yame fetch -n hg38/data
hg38/data: 7 files in 1 directory, 51.0 MB
  human_hg38_40_celltypes_chr20.cg               39.5 MB
  human_hg38_celltypes.cg                         6.1 MB
  human_hg38_immune_mixture.cg                    3.5 MB
  human_hg38_test.truth.cg                        1.9 MB
  human_hg38_test.cg                            101.3 KB
  human_hg38_40_celltypes_chr20.cg.idx            2.1 KB
  human_hg38_celltypes.cg.idx                       96 B

Files already in the store are counted separately and not re-fetched, so the size quoted is the transfer rather than the total on disk. When that leaves nothing to do it says so and stops — no prompt:

hg38 -g celltype: all 6 files already in the store.

On a terminal a bare fetch opens a picker; inside it / filters the tree on those same facets, enter fixes the view so you can select in it, and esc clears it. Piped or redirected, fetch dumps the registry as TSV instead, so a script never blocks on a keystroke.

yame fetch -l | cut -f1,2,5,6 | head -5
target	source	file	bytes
EPIC	InfiniumAnnotation	EPIC.ordering.tsv.gz	7756709
EPIC	InfiniumAnnotation	EPIC.hg38.coord.tsv.gz	5505138
EPIC	InfiniumAnnotation	EPIC.hg38.snp.tsv.gz	1776995
EPIC	InfiniumAnnotation	EPIC.typeI_ext.tsv.gz	91446

-l takes the same name and -g a fetch does, so it is the machine-readable form of the same question.

yame fetch -l hg38 -g methscope   # exactly what that fetch would take
yame fetch -l | cut -f1 | sort -u  # every name you can fetch
yame fetch -l | awk -F'\t' '$9=="no"'  # what the store is missing

Every row carries size, sha256, description and whether the store already holds it. A directory records which upstream tag filled it and refuses to mix tags — a row reading stale tag: -f wants yame fetch -f <name>.

Storage scheme — position is implied, never stored

A YAME file is values in order and nothing else. Row i means whatever row i of the reference means, so intersecting a methylome with a feature set is a bitwise AND rather than a genomic join — fast, and indifferent to how many rows there are.

Two files are comparable only if they share a row space, and since each has a distinct length, a row count is an identity. That is what lets -R and -m take a name instead of a path. An Infinium manifest and a whole-genome CpG set are the same kind of object here, differing only in length.

The seven formats — one record header, seven packings

They differ only in what one row costs and what it can say. A presence/absence mask does not need a byte per CpG; a coverage track cannot live in a bit.

Two bits is the interesting one: the universe bit separates not measured from measured and zero — a distinction one bit cannot make and every enrichment test needs, which is why a query and its background travel in one file.

Data conversion — text in, text out

pack is the only way in. Input is one row per CpG already in the reference's order — nothing is sorted or matched for you.

yame unpack -R hg38 human_hg38_test.cg | awk '$4!=2' | head -5
chr1	659296	659298	1
chr1	779099	779101	0
chr1	795737	795739	1
chr1	933194	933196	0
chr1	958160	958162	1

Format 6 prints one column by default; -f -1 gives set and universe separately, which is what pack -f6 reads back:

yame unpack -f -1 human_hg38_test.cg | awk '$1!="NA"' | head -3
1	1
0	1
1	1
yame pack -f6 rt.txt rt.cg  # and back again

Verified byte-identical on the round trip.

Visualization — look at it without leaving the shell

Rows are samples, columns are CpGs or windows. The reference is inferred from the row count, so -r alone is enough.

yame hprint -r chr20:30000000-30001000 human_hg38_celltypes.cg
                      chr20:30000011-30000862 (10 CpGs)
                      |.........
                      30000011  
Oligodendrocyte       █...██..░█
Pancreas-Beta         █.....░█..
Blood-NK              ....██░█░█

-w caps the width — wider regions are window-averaged rather than truncated — and -R alone gives the whole-genome view.

Multi-sample indexing — many samples, one file

Records concatenate, so a cohort is one file. The .idx beside it maps sample names to offsets, which is what makes them addressable by name.

yame info human_hg38_celltypes.cg | cut -f2-7
Sample	Ncol	Nrow	Format	UnitBytes	Keys
Oligodendrocyte	4	29401795	6	2	NA
Pancreas-Beta	4	29401795	6	2	NA
Blood-NK	4	29401795	6	2	NA
Blood-Monocytes	4	29401795	6	2	NA
yame chunk -s 500000 cohort.cg chunks/  # fixed row blocks, for parallel work
yame subset -o two.cg human_hg38_celltypes.cg Blood-NK Blood-Monocytes
yame split -s names.txt human_hg38_celltypes.cg out_  # one file each
yame index -s names.txt cohort.cg  # rebuild the index
Sample	Nrow	Format
Blood-NK	29401795	6
Blood-Monocytes	29401795	6

Compare & summarize — the analysis command

With no mask, summary describes the file. With one it gives the overlap table — universe, query, mask, overlap, log2 odds ratio, beta, depth. The mask is named, not spelled out: the query's row count says which row space to resolve it in.

yame summary -m CGI human_hg38_test.cg
QFile	Query	MFile	Mask	N_univ	N_query	N_mask	N_overlap	Log2OddsRatio	Beta	Depth
human_hg38_test.cg	1	CGI.20220904.cm	OpenSea	29000	23857	23534	21149	3.17	0.899	NA
human_hg38_test.cg	1	CGI.20220904.cm	Shelf	29000	23857	1224	1076	0.67	0.879	NA
human_hg38_test.cg	1	CGI.20220904.cm	Shore	29000	23857	2074	1263	-1.74	0.609	NA

A format 2 mask yields one row per state, so -m ChromHMM tests every chromatin state at once. -b picks the set in the browser instead.

yame binarize -t 0.5 -c 3 -o calls.cg mix.cg  # M/U -> set + universe
yame pairwise -H 1 -c 5 -d 0.2 a.cg b.cg  # differential, fmt3 -> fmt6
yame rowop -o binasum cells.cg pseudobulk.cg  # collapse across samples
Sample	Nrow	Format
1	773477	3

That last one is how pseudobulks are made: subset the cells of a cluster, pipe into rowop.

Perturb & mask — for benchmarking

Two different jobs. mask is deterministic and file-driven — it decides which sites are valid. dsample and perturb are stochastic and seed-driven — they decide how much signal is left.

yame dsample -N 5000 -s 42 -o ds.cg human_hg38_test.cg
Query	N_univ	N_query	Beta
0	5000	4087	0.817
yame perturb -p 0.05 -s 7 -o noisy.cg human_hg38_test.cg
Query	N_univ	N_query	Beta
1	29000	22953	0.791

Set -s. Without a fixed seed neither is reproducible. mask takes its mask as a positional argument, not -m, and both files must have the same row count.

yame mask -o clean.cg sample.cg blacklist.cm
