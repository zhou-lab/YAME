The idea

A YAME file stores no coordinates. Row i means whatever row i of the reference means — so the file is just values, in order, packed as tightly as the measurement allows.

Everything else follows from that. Intersecting a methylome with a feature set is a bitwise AND rather than a genomic join, so it is fast and it does not care how many rows there are. Two files can be compared only if they share a row space, and since each row space has a distinct length, a row count is an identity: given a file, YAME can work out which reference it belongs to and resolve -R and -m from a name instead of a path.

An Infinium manifest and a whole-genome CpG set are the same kind of object under that rule, differing only in length — which is why the same commands serve array and sequencing data.

Which format do you need?

Seven layouts, one record header. They differ only in how much space one row costs and what it can say — a presence/absence mask does not need a byte per CpG, and a coverage track cannot live in a bit. Find your data on the left; open a row for the layout, an example and the traps.

You have Fmt On disk NA? pack
M/U counts from bisulfite sequencing 3 1–8 B / site M=U=0 -fm

Two integers per site: reads supporting methylated, reads supporting unmethylated. Coverage is M+U and the fraction is M/(M+U), so nothing is lost to rounding before you decide how to threshold.

# input: tab-delimited, column 1 = M, column 2 = U, one row per CpG
yame pack -fm sample_MU.txt sample.cg

Worth knowing

  • Counts are lossy at the top end. A site is stored in 1, 2 or 8 bytes depending on how big the counts are; when they overflow the chosen width both M and U are right-shifted together. The ratio survives, the absolute depth does not.
  • NA is M=U=0 — there is no separate missing flag. Runs of uncovered sites cost 2 bytes per run, not per site, so a sparse single-cell methylome stays small.
  • -u <1-8> sets the in-memory width; leave it alone unless you know why you are changing it.
Beta values — array, or imputed 4 4 B / value yes -fn

The methylation fraction itself, one float per row. Use it when the counts are gone or never existed — an Infinium β, or a fraction someone else already computed.

# input: one float per line, "NA" allowed
yame pack -fn betas.txt sample.cg

Worth knowing

  • NA is stored as a negative value, so it is distinguishable from a true zero — and consecutive NAs collapse into a single run, which is why an array manifest with large unmeasured stretches does not pay for them.
  • Anything that does not parse as a number becomes NA. That is forgiving on input and silent about typos: check the row count with yame info after packing.
A yes/no per CpG — a feature set or mask 0 1 bit / row no -fb

The densest thing here: one bit per CpG, so a whole-genome hg38 track is 3.5 MB. This is what a mask is, and what most of a knowledgebase is made of.

# input: one value per line, 0 or 1, one row per CpG
yame pack -fb in_island.txt CGI.cm

Worth knowing

  • Only 0 means zero. A line is read as 1 unless its first character is 0 — so NA silently becomes a member of the set. Format 0 has no way to say "not measured"; if you need that distinction you want format 6.
A set plus which sites were measured 6 2 bits / row yes -fd

Two bits: one says the site was measured at all (the universe), one says it is a member (the set). That second bit is the whole point — it separates absent from present-and-zero, which one bit cannot do and every enrichment test needs.

# input: tab-delimited, column 1 = set (0/1), column 2 = universe (0/1)
yame pack -fd calls.txt sample.cg

Worth knowing

  • The set bit is set only by the exact string 1. 1.0, TRUE and 01 all read as 0. The universe column is more forgiving: any non-zero number counts.
  • A query and its background travel in one file, which is why summary can produce an odds ratio from a single record.
Categorical labels — chromatin states 2 dictionary + runs a label -fs

Arbitrary string labels per row, stored once in a key table with the rows as indices into it, then run-length encoded. Adjacent CpGs are almost always in the same state, so this compresses hard.

# input: one label per line -- the whole line is the label
yame pack -fs chromhmm_states.txt ChromHMM.cm
yame info ChromHMM.cm          # the Keys column lists every state

Worth knowing

  • NA is just another label, not a missing marker: empty lines become the literal string NA and get a key like any other state.
  • yame subset -s explodes one state track into a separate format-0 bitset per state, which is how a state file becomes testable sets.
One small integer or character per CpG 1 3 B / run no -fc

A single byte per row, run-length encoded. Niche — useful for a small per-site code where format 2's key table would be overkill.

yame pack -fc codes.txt codes.cg

Worth knowing

  • Only the first character of each line is stored. Despite what the range "0–255" suggests, 37 is stored as the character 3. If your values are multi-digit, this is the wrong format — use format 3 or 4.
The coordinates themselves — a row space 7 delta, 1/2/8 B n/a -fr

The reference itself: every position in a row space, in order, as gaps between consecutive positions rather than absolute coordinates. This is the .cr file that gives every other format its meaning.

yame pack -fr cpg.bed cpg_nocontig.cr

Worth knowing

  • Only the first two columns are read — chromosome and start. The usage text mentions a 4-column BED, but name and end are ignored.
  • Input must be sorted. A coordinate that goes backwards is not an error: it silently begins a new chromosome block, and you get a corrupt row space that still loads.
  • You rarely build one of these. yame fetch ships the standard ones for all ten row spaces.

Format 5 — a ternary 0/1/NA layout — is obsolete. Old files still decode; nothing writes it. Format 6 replaced it.

What can you run?

Eighteen commands. The strip on the right of each row is the seven formats — filled means it reads that format, outlined means it writes it, faint means it does not handle it. Open a row for the flags that matter and an example.

Get data in and out

pack Text → .cx, one row per CpG 0123467

The only way in. Input is a plain text/BED file with one row per CpG, already in the reference's order — nothing is sorted or matched for you, and nothing checks that you got it right, so a misaligned input produces a file that loads cleanly and means nothing.

Which -f to use is the whole of the table above.

yame pack -fm sample_MU.txt sample.cg

Every flag: yame pack -h

unpack .cx → text, one column per sample 0123467

Reads every format. By default it prints only the first record — -a is what you almost always want.

yame unpack -a -C -R hg38 sample.cg > sample.tsv
  • -a all samples, -C header line.
  • -R <ref|name> prepends the coordinate columns. Not inferred here — leaving it off is a legitimate request for a bare value column.
  • -f controls rendering: for format 3, a negative value prints M and U in separate columns; a positive one prints beta with a coverage floor.

Every flag: yame unpack -h

chunkchar Split a big text file by line count, before packing 0123467

Plain text in, plain text out — the pre-pack companion to chunk. Output always lands in <input>_chunks/.

yame chunkchar -s 1000000 big_MU.txt

It reads the whole file into memory first, so for very large inputs split(1) is the better tool.

Every flag: yame chunkchar -h

Look at it

info Row count, format, sample names — start here 0123467

One line per record. The row count is the useful part: it identifies the row space, which is what lets -R and -m be given as names instead of paths.

yame info -1 *.cg

For a format 2 file the Keys column lists every state label.

Every flag: yame info -h

hprint Terminal heatmap of a region or the whole genome 0123467

Look at the data without leaving the shell — rows are samples, columns are sites or windows.

yame hprint -r chr16:10000000-10100000 cohort.cg
  • -r <region> zooms in; -R gives the whole-genome view. The reference is inferred from the row count when you give -r alone.
  • -w caps the column count; wider regions are window-averaged rather than truncated.
  • Without -r or -R it only accepts format 6.

Every flag: yame hprint -h

Manage files

index Build the sample index so names work 0123467

Writes the .idx beside a .cx, mapping sample names to record offsets. Without it, a multi-sample file can only be read positionally.

yame index -s sample_names.txt cohort.cg

Every flag: yame index -h

split One file per sample 0123467

Records are copied verbatim, so the output format always matches the input.

yame split -s sample_names.txt cohort.cg out/

Names come from -s, not from the index; without it you get split_1.cx, split_2.cx, …

Every flag: yame split -h

chunk Cut a file into fixed-size row blocks 0123467

For parallelising work over row ranges. Chunks are numbered from zero and concatenate back to the original.

yame chunk -s 500000 cohort.cg cohort_chunks

Formats 2 and 7 are refused: a state track carries a key table ahead of its rows and a .cr is a delta stream, so neither survives being cut at an arbitrary row. Use rowsub, which understands both.

Every flag: yame chunk -h

Subset it

subset Pick samples out of a multi-sample file 0123467

Columns, not rows. Needs the .idx.

yame subset -o sub.cg cohort.cg SampleA SampleB
  • -l <list> a file of names; -H/-T <N> the first/last N.
  • -s is a different command in disguise: on a format 2 state track it emits one format 0 bitset per state — the usual way to turn chromatin states into testable sets.
  • Writing with -o also builds the output index; piping to stdout does not.

Every flag: yame subset -h

rowsub Slice rows — by index, coordinate, mask or block 0123467

The row-wise counterpart to subset, and the one that handles every format correctly.

yame rowsub -L targets.txt cohort.cg > sub.cg
  • -l row indices, -L genomic coordinates, -m keep where a mask bit is 1, -B/-I a contiguous block.
  • -R is inferred from the row count when -L needs it.
  • The mask must be format 0 or 1.

Every flag: yame rowsub -h

Compare and summarize

summary Global statistics, or a query against a feature set 0123467

The main analysis command. With no mask it describes the file; with one it produces the overlap table — universe, query, mask, overlap, log2 odds ratio, beta, depth.

yame summary sample.cg                     # global statistics
yame summary -m ChromHMM sample.cg         # against a knowledgebase set
yame summary -b sample.cg                  # or pick the set in the browser
  • -m takes a name, not just a path — the query's row count says which row space to resolve it in.
  • Every mask sample is crossed with every query sample.
  • A format 2 mask yields one output row per state, which is how you test against all chromatin states at once.

Every flag: yame summary -h

pairwise Differential methylation between two samples 0123467

Compares two format 3 samples site by site and writes the calls as a format 6 track — the universe bit marks sites with enough coverage in both, the set bit marks the ones that differ.

yame pairwise -H 1 -c 5 -d 0.2 tumor.cg normal.cg > hyper.cg
  • -H 1|2|3 hyper, hypo, or any difference; -c minimum coverage; -d minimum |Δbeta|.
  • With one input file it compares that file's first two records.
  • Give it format 3. Other formats are not rejected — they are misread.

Every flag: yame pairwise -h

rowop Collapse across samples at each row 0123467

Goes down the columns: how many samples are methylated here, what is the summed coverage here. This is how pseudobulks are made.

yame subset -l cluster1.txt cells.cg | yame rowop -o binasum - pseudobulk.cg
  • -o binasum (the default) counts methylated vs unmethylated samples per row and emits format 3; it is the only op that accepts formats 0 and 1.
  • musum sums M and U; stat, binstring and cometh emit text. All four need format 3.
  • -c sets the minimum coverage for a cell to count at all.

Every flag: yame rowop -h

binarize M/U → set + universe, by threshold 0123467

Turns counts into calls: coverage decides the universe bit, a beta or M threshold decides the set bit. Usually the step before summary.

yame binarize -t 0.6 -c 5 -o sample.b.cg sample.cg
  • -t beta threshold (default 0.5), -c minimum coverage.
  • -m <Mmin> overrides -t when set above zero.
  • Depth does not survive: format 6 keeps no coverage, so summary reports NA in that column afterwards.

Every flag: yame binarize -h

Perturb, for benchmarking

mask Invalidate specific sites from a file 0123467

Deterministic and file-driven — it controls which sites are valid. Format 3 sites are zeroed, format 6 sites set to NA, format 0 bits cleared.

yame mask -o clean.cg sample.cg blacklist.cm
  • The mask is the second positional argument, not -m, and it is required.
  • Mask and data must have identical row counts.
  • -v inverts; -c promotes a format 0 input to format 6, using the mask as the universe.

Every flag: yame mask -h

dsample Randomly keep N sites, mask the rest 0123467

Stochastic and rate-driven — it controls how much data is left. For coverage-titration experiments.

yame dsample -N 1000000 -r 5 -s 42 -p ds -o ds.cg sample.cg
  • -N sites to keep, -r independent replicates per input sample.
  • -s fixes the seed — set it, or the run is not reproducible.

Every flag: yame dsample -h

perturb Flip bits at a given rate 0123467

Noise injection, for testing how far a method degrades.

yame perturb -p 0.02 -s 7 -o noisy.cg binary.cg

-p is the per-bit flip probability. On format 6 only in-universe sites are eligible, so NA stays NA.

Every flag: yame perturb -h

Reference data

fetch Download row spaces and knowledgebases into the store 0123467

Nothing ships with the binary. This fills the shared store that -R hg38 and -m ChromHMM resolve against, verifying every file against a digest compiled into this build.

yame fetch                     # browse: species, platform, then files
yame fetch -l                  # dump the registry as TSV
yame fetch -l | cut -f1,2 | sort -u          # every fetchable target
yame fetch -l | awk -F'\t' '$9=="no"'        # what the store is missing
  • The browser needs a terminal; piped or redirected, fetch dumps the registry instead so a script never blocks.
  • A directory records which upstream tag filled it and refuses to mix tags. A row reading stale tag: -f needs yame fetch -f <source>/<target>.

Every flag: yame fetch -h

Glossary

The words this manual leans on. Every dotted term on the page points here, and shows the same text on hover.

CX format
The family of binary layouts YAME reads and writes — formats 0 through 7. All of them share one record header and differ only in how the data after it is packed.
record
One header plus one blob: an 8-byte signature, the format code, the row count, then the packed data. A file is records concatenated, one per sample.
row space
The ordered list of positions a file's rows refer to. Nothing in a data file says where row i is — it means whatever row i of the reference means, so two files intersect only if they share a row space.
reference (.cr)
A format-7 coordinate stream naming every position in a row space, in order. cpg_nocontig.cr is the whole-genome one; an array's equivalent is its probe ordering.
universe
In format 6, the set of positions that were measured at all. The universe bit is what separates not measured from measured and zero — a distinction a plain bit vector cannot make and every enrichment test needs.
set
In format 6, the positions that are members — the query. Carried in the second bit, alongside the universe bit, so a query and its background travel in one file.
M / U
Methylated and unmethylated read counts at a position, stored side by side in format 3. Coverage is M+U; the fraction is M/(M+U).
beta
The methylation fraction at a position, M/(M+U), between 0 and 1. Format 4 stores it directly when the counts are not needed.
.cg / .cm
Conventional suffixes, not different formats: a .cg holds methylation data for a sample, a .cm a feature set or mask. Both are CX records over some row space.
mask
A second file, aligned to the same row space, that selects which rows count. Intersecting it with data is a bitwise operation rather than a genomic join.
knowledgebase
A collection of feature sets for one row space — chromatin states, CpG islands, repeats, TF binding — that a query is tested against. Fetched into the store, not shipped with the binary.
the store
Where fetched reference data lives, shared by every tool that links libyame. Its location is $YAME_DATA_HOME, or ~/.local/share/yame.
BGZF
The block-compressed format the records sit inside. Compression is per block, so any record can be reached without decompressing the ones before it.
index (.idx)
A sidecar listing sample names and where each record starts, so one sample can be pulled from a file of hundreds without reading the rest.
